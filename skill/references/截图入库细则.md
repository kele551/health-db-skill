### 7.3.1 先判是不是我的活（2026-11-15 起，第一步就做）

用户丢图/发语音时不会说"这是化验单"，**先认类型再分派；本技能只接日常测量类，别的类型转走，别硬塞进三张表**。

| 图上特征 | 判为 | 去哪 |
|---|---|---|
| 华为运动健康「今日」/「数据汇总报告」、三诺健康、血压/血糖/体重/步数/睡眠卡片 | 日常测量 | **本技能**（`健康录入.py`） |
| 「检验报告单/化验单」+ 结果·单位·参考区间·检测方法 | 化验单 | `health-db` §3.1 → `化验单入库.py` → `检查结果.csv` |
| 「超声/MRI/CT」+「影像所见/诊断意见」 | 影像报告 | `health-db` §3.1 → 档案卡 `imaging` |
| 「病理报告单/免疫组化/病理号」 | 病理报告 | `health-db` §3.1 → 档案卡 `pathology` |
| 「结算明细/使用记录查询」（总费用·现金·基金·个账支付） | 医保结算 | `health-db` §3.1 → 中药总表三列 |
| 「费用清单」（单价·数量·金额·医保编码） | 医保费用清单 | `health-db` §3.1 → 中药总表 + 费用清单明细 |
| 中药处方（药材/付数/单付） | 中药方 | `health-db` §3.1 → 中药总表 |
| 只有一句话（语音转字） | 文本 | 有数值 → `健康录入.py --text`；只有感受（睡不好/大便两三天一次/乏力）→ 症状记录 |

**只回文字不算做完（2026-11-15 硬加）**：用户发图或说完话之后，必须真的跑命令，并用「行数变化 / release_id / 文件 version」证明落地。禁止出现「我来识别…」「已追加归档」「自动执行中」这类话而底下没有工具调用。完整意图→命令对照表见 `health-db` §3.2（写死版），照表执行，不另行发挥。

**换窗口就失忆，先查台账（2026-11-15 硬加）**：不同 AI 对话窗口之间上下文不共享，图不会跨窗口共享。收到图先跑 `单据台账.py check "<日期/文件名>"`，命中说明这张早已入库，直接报核对结果、不重复录；没命中再走本技能，收尾跑 `单据台账.py build` 刷新台账并同步到外部存储（可选）。口径见 `health-db` §3.3。

判别口诀：抬头标题 + 要素词（结果/参考区间=化验；影像所见=影像；病理诊断=病理；总费用·支付方式=医保；单价·数量=费用清单；付数·单付=中药方）。一张长图混多种就按段落各自归属。判不准只问一句，问过就记住。

### 7.4.1 六步分工（谁负责哪一段）

| 步骤 | 谁做 | 落在哪里 |
|---|---|---|
| 识别 | OCR + 文字解析（三遍投票，认不准就进待确认） | 屏幕上的数字 → 结构化字段 |
| 读取 | 先读外部存储里的三张表再合并（可选） | `归档原始\*.csv`（本地正本） |
| 入库 | 并集追加，同一天多次测量各留一条 | 血压血糖 / 日健康指标 / 体重记录 |
| 归类 | 日常指标与档案数据分流 | 日常 6 类；档案：化验/用药/复查 |
| 分析 | `健康数据库.py check` 规则引擎 | `监测.json` 16 项判定 + 复查到期 |
| 建议 | 规则命中生成建议（不给剂量、不做诊断） | 页面「健康监测」的建议段 |

页面顶部「工作流 识别→读取→入库→归类→分析→建议」是这条链的可视化，后面的数字实时算。

脚本自动完成：读库现有行 → 并集合并（不覆盖已有行）→ 超长图自动切片 OCR（>2200px 切 1400px、90px 重叠）→ 血压/血糖/日指标/体重四类解析器**都跑一遍**（华为「今日」长截图是混合页）→ 按内容去重写库 → 图片归档 → 整库覆盖同步到外部存储（可选）。

**多遍识别复核（2026-11-15 起，最重要的一条）**：同一张图识别 3 遍（原图、放大 2 倍、放大 3 倍宽松阈值）；某个数值要在 3 遍里至少 2 遍一致才采信，只出现 1 遍的写进 `日志\待确认入库.csv` 并提示本人核对，**绝不进正式表**。识别倍数与自适应阈值见脚本 `ocr_text(image, loose, scale)`。

**没有日期就不入表**：`explicit_date()` 只认截图里看得见的 `YYYY-MM-DD` / `YYYY年MM月DD日` / `M月D日`。认不出日期时血压/血糖只进待确认；本人说清哪天后用 `--force-date YYYY-MM-DD` 重跑同一张图。禁止拿图片文件时间当测量日期（2026-11-15 的假血压/血糖就是这么来的）。

**体重**：华为「今日」页的体重卡片（体重 kg / BMI / 体脂率 / 肌肉量）写进 `体重记录.csv`；同一天已有行就只补空字段。页面写「今日」才允许用今天，否则同样要求看得见的日期。

**大号数字漏检的兜底**：华为「今日」页的睡眠卡片是超粗大号数字（如「5 小时 54 分钟」），RapidOCR 整图会漏掉单独那个「5」。脚本里 `sleep_from_card()` 会自动：整图找到「睡眠」标签坐标 → 裁卡片 → 用宽松检测参数（box_thresh 0.2 / text_score 0.3 / unclip_ratio 1.8）再识别 → 按「小时」左右两侧的数字拼成小时和分钟。已用真实截图验证得到 354 分钟。

**华为数据报告（.docx）也能直接入库**：用户从华为运动健康导出的「数据汇总报告」word，用同一条命令 `--file "<报告.docx>"` 即可，脚本解析其中「近 7 天睡眠」「近 7 天心率」「历史血压」三类，按日期补进日指标与血压表（已有的日期只补空字段）。

其它参数：`--dry-run`（只识别不写）、`--no-cloud`（不拉不传）、`--upload`（带上才传外部存储；Windows 计划任务环境不要带，会 rc=3）。

### 7.4.2 四种输入，一个入口（电脑端＝手机端，2026-11-22 用户定）

用户原话：「一句话、一张截图、一段文字、一张照片都能识别录入数据库，不论电脑端还是手机端」。所以**不按设备分流程，只按内容分**，入口永远是 `健康录入.py`。

| 发来的是什么 | 怎么落 | 落到哪 |
|---|---|---|
| 一句话 / 语音转写 | `--text "…"` | 血压血糖 / 日指标 / 体重 |
| 一段文字（多行、含日期） | `--text "…"` 带换行，或先存 `.txt` 再 `--file` | 同上，逐句解析 |
| 截图（电脑或手机） | 先落到本地绝对路径 → `--file "<path>"` | 同上，三遍投票 |
| 照片（拍纸单 / 拍屏） | 同截图；要求四角拍全、不反光、字迹清楚 | 化验单→化验流程；日常卡→三张表 |
| 单据 / 处方 / 费用清单照片 | `quick_kind` 判 `unknown` → **不猜、不进三张表** | 提示核对原件，转 `health-db` 单据流程 |

- **手机端没有本地盘**：附件只有 URL 时先下载到 `%TEMP%`（或会话工作区）再传路径，别让用户自己建文件夹、改名。
- **电脑端**：直接把窗口里的路径传进去即可；拖进豆包对话框的图同样先落本地。
- 同一条命令可一次收多张：`--file a.png b.png c.txt`，内部按扩展名与图像类型自动分流。
- 口语睡眠支持「睡了6个半小时」「睡七个半钟头」＝7.5 小时（`健康文字录入.py` 已加，2026-11-22）。
- 入库只认「看得见的日期」：截图里没日期、话里也没说日期 → 按今天记并在回话里写明；单据必须原件有日期。

### 7.4.3 看图识别统一流程（2026-11-22 用户定死：「以后就按照这套看图逻辑」）

**任何图片 / PDF 取字，一律走 `<ROOT>\tools\看图识别.py`，不许各脚本自己 new RapidOCR。**

```powershell
$PY = "<ROOT>\toolchain\python\envs\default\Scripts\python.exe"
& $PY -X utf8 "<ROOT>\tools\看图识别.py" "<图片或PDF>"          # 打印文本
& $PY -X utf8 "<ROOT>\tools\看图识别.py" "<文件>" --json          # 带坐标与置信度
& $PY -X utf8 "<ROOT>\tools\看图识别.py" "<文件>" --crop 0.0,0.40,1.0,0.52 --zoom 4   # 疑点裁块放大
```

顺序固定，不许倒：
1. **PDF 先抽文字层**（pypdf）——电子版病理/报告直接拿原文，不过 OCR；抽不出（扫描版）才提示改用截图。
2. **图片双通道**：原图 + 2 倍 LANCZOS 放大各识别一遍，按行合并去重，同文本取高分（实测 1280×1819 化验单原图 5.5 s / 双通道 9 s，小字明显更稳）。
3. **疑点回看**：数值或名称对不上时，用 `--crop` 按行裁一条（y±30 像素、整幅宽）放大 3–4 倍单独看，**以人眼看到的原单为准**再决定改不改库。
4. **缓存**：同一文件同一缩放不重复算，缓存在 `%TEMP%\health_ocr_cache`；改完识别逻辑要删缓存重跑。
5. 给脚本调用：`sys.path.insert(0, r"<ROOT>\tools"); import 看图识别 as SEE; SEE.read_text(path)` / `SEE.read_blocks(path)`。
6. 已接入：`单据识别.py` 的 `ocr_text()` 已改为调它；`化验单入库.py` / `健康截图入库.py` 里有华为大号数字的专用兜底逻辑（`sleep_from_card`），属于同一套流程的特例，**不要为了统一把兜底删掉**。

### 7.6.1 完成验收清单（入库 + 刷新后逐条核对）

- **行数对得上**：本次新增条数 = 原件可识别项目数；化验单/单据逐行核对，行数必须等于原单项目数，不合并、不省略阴性或 0 值项。
- **值/单位/区间照抄**：结果、单位、参考区间与原件一致；mg/dL 已按 ÷18 换算并备注原值；时点、时间识别不出就留空，不猜测、不编。
- **不达标不入表**：三遍投票不足两遍一致、无可见日期、越出生理合理区间的，一律进 `日志\待确认入库.csv`，回话点明要核对哪一件。
- **外部存储已落地（可选）**：`.db` 覆盖上传成功，回读核对 `file_name` + `size` + `version`；回话报文件名、大小、版本号，不能只说"已同步"（跨端存储按使用者自己的那端执行，任意外部存储（网盘 / 云盘 / NAS）性质相同）。
- **页面已生成**：总览页重新生成本地 HTML 文件；链接/发布状态是历史写法，现行不发链接；改过页面先过 `node --check` 语法 + headless 截图眼见两道自检。
- **证据闭环**：用「行数变化 / 文件 version」证明真落地；禁止只回"已识别/已归档/执行中"而底下没有工具调用。

### 7.7 口径（不可改）

- 表结构照单文件库 `医疗与运动健康数据库.db` 的三张表原样（`bp_glu` / `daily` / `weight`，对应旧 CSV 血压血糖 / 日健康指标 / 体重记录），不加列、不改列名。注意 `bp_glu.kind` 取值是中文「血压」「血糖」，统计时别写 `kind='bp'/'glu'`（会得 0 行）。
- 血糖时点枚举：空腹 / 睡前 / 晚餐后 / 晚餐前 / 午餐后 / 午餐前 / 早餐后。
- 表头「早餐前」= 数据里的「空腹」时点，用户已确认这个映射是对的。
- 达标：空腹与餐前 4.4–7.0；餐后与睡前 <10.0；<3.9 记低血糖。血压以国标为准：合并糖尿病/慢性肾病 <130/80（《中国高血压防治指南 2024 修订版》），舒张压不低于 70（保单肾灌注）；参照国际：2024 ESC 收缩 120–129、KDIGO 2021 非透析 CKD <120。目标值统一从 `<ROOT>\tools\健康目标口径.py` 取，按年龄分档，别在别处另写。
- 时点、时间没识别出来就留空，不猜测、不编。
- 生理合理区间：血糖 1.0–40 mmol/L、血压 收缩 70–260 / 舒张 40–160、体重 25–250 kg，越界直接判为误识别。
- 血糖仪显示 mg/dL 时按 ÷18 换算成 mmol/L 入库，备注里留「原 xxx mg/dL 换算」。
- 新值与近 90 天均值差太多（血糖 >3.0 mmol/L、收缩压 >35 mmHg）照原值入库，但备注标「请复核」并在回话里点出来。
- **录入必须与原件逐项一致（2026-11-18 用户定，最高优先级）**：化验/影像/病理单据入库时，原件上**每一行都写成一条记录**——项目名、缩写、结果、单位、参考区间**照抄原单**；不合并同类、不省略阴性或 0 值项、不做单位换算、不按经验改区间。同一张单入库后**行数必须等于原单项目数**（逐日期核对），缩写撞名的加限定（如尿 `WBC(尿)`、`NSE(尿)`）。原件与库不一致时**一律改库、以原件为真**（读取原件所得的判断就是最终结论），并回报改了哪几处、每类补了几行。
- 一人一份：档案卡在 `医疗与运动健康数据库.db` 的 `profile` 表（原 JSON 文件已删，读写走 `健康库.profile()/set_profile()`），数据也都在同一份 .db 的对应表里（**换人＝换一份独立 .db 文件，物理隔离、互不相通**）。
